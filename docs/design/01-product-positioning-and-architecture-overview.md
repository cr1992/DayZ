## 1. 产品定位与核心需求

做一款 **本地优先（local-first）、注重隐私、体验精致** 的跨平台日记应用，对标 Day One。

核心需求：

- **跨平台**：优先 iOS / Android，桌面端为远期可选。
- **富文本编辑**：图文混排、拖拽插入图片、丰富样式（标题/列表/引用/代码/待办等）。
- **时间线**：无限下拉/上滑，几千上万条带图日记流畅预览，按年-月分组、吸顶。
- **往年今日**：快速回顾历史上同一天（月-日匹配）的记录，可做成每日推送回访。
- **备份与导出**：区分”机器用的无损备份”与”给人看的可读归档”；备份支持全量/增量；数据可完整带走。
- **隐私加密**：本机数据与备份均加密，体现日记产品的信任承诺。
- **远期能力（预留，暂不实现）**：多端同步、全文搜索。

设计原则：**本地优先 + 数据可完整带走 + 默认加密**。同步在架构上预留字段不实现；加密则在本版纳入，因其与备份/还原深度耦合，事后追加代价大。

## 2. 技术选型总览

|层      |选型                                     |状态|说明                                       |
|-------|---------------------------------------|--|-----------------------------------------|
|跨平台框架  |**Flutter**                            |定稿|一套 Dart 多端运行，时间线/Sliver 是其强项             |
|本地数据库  |**Drift（SQLite ORM）**                  |定稿|类型安全 + 响应式查询，关系型查询能力是刚需                  |
|数据库加密  |**SQLCipher**（`sqlcipher_flutter_libs`）|定稿|数据库文件始终密文，对上层查询近乎无侵入                     |
|密钥派生   |**Argon2id**（独立模块）                     |定稿|备份口令派生密钥；远期 E2E 复用同一模块                   |
|敏感小数据  |**flutter_secure_storage**             |定稿|本机随机密钥、解锁口令，走钥匙串/Keystore                |
|普通设置   |**shared_preferences**                 |定稿|主题、排序偏好等非敏感配置                            |
|媒体存储   |**文件系统**                               |定稿|库内只存相对路径 + 宽高；媒体单独加密                     |
|富文本编辑器 |**AppFlowy Editor（方案 A）**              |定稿|2026-05-29 预研后定（见 4、5.1 节）；纯 Dart，图片交互经 vendored 源码补强|
|全文搜索   |**SQLite FTS5**                        |远期|本地明文索引，永不上传，天然兼容加密                       |
|导出/备份  |**Dart + isolate**                     |定稿|见第 8 节备份架构                               |
|重计算（可选）|**Rust via flutter_rust_bridge**       |按需|仅实测出瓶颈或做核心引擎时引入                          |
|同步（远期） |待评估                                    |远期|Supabase / PowerSync / ElectricSQL / CRDT|

**架构理念**：界面、列表、数据、备份全部 Flutter 实现；编辑器作为相对独立、可替换的一块单独选型，不阻塞主流程。

## 10. 关于引入 Rust（结论：暂不需要，按需再上）

- 导出/备份瓶颈大概率在 **I/O**（读图、压缩、写盘），Rust 与 Dart 差距小；真正吃 CPU 的是**图片批量重编码 / 大批量 PDF 渲染**。
- **Dart isolate 已能解决卡 UI**，纯 Dart + isolate 对备份/导出体验完全可接受。
- Rust 代价：FFI 工具链、各平台交叉编译、CI 改造、跨语言调试、包体积、多养一门语言。
- **路径**：先纯 Dart + isolate 实现并测真实耗时；若某环节确为瓶颈（几乎只会是图片重编码或 PDF 渲染），**仅该环节**下放 Rust，边界干净（入字节、出字节）。
- **例外**：若规划用 Rust 写跨平台核心引擎（同步 / 加密 / CRDT，如 AppFlowy 后端即 Rust），则早搭 Rust 工具链值得，备份顺带受益——属更高层架构决策。

## 13. 参考与对标

- **Day One**（Bloom Built / Automattic）：主要对标——时间线、往年今日（On This Day）、多 Journal、媒体日记、加密同步、导出（PDF/JSON/Markdown）。
- **Journey**：跨平台（含 Web/Android）日记，云同步、Markdown，参考其多端策略。
- **Diarium**：多平台、本地优先 + 可选云盘同步，导出格式丰富，参考其导出与同步取舍。
- **Obsidian**：本地优先 + Markdown 文件库 + 插件生态典范，参考其”文件即数据、抗锁定”理念。
- **AppFlowy**：开源 Notion 替代，Flutter UI + Rust 后端，其 Editor 为方案 A 来源，其架构为远期引擎化参照。
- **TipTap / ProseMirror**：方案 B 基础，富文本编辑事实标准之一。
- **SQLCipher**：成熟的 SQLite 加密方案，本方案数据库加密选型。
- **PowerSync / ElectricSQL**：local-first 同步层近年代表，远期同步参考（PowerSync 可与 Drift 配合）。
- **Automerge / Yjs**：CRDT 库，富文本并发合并参考。
